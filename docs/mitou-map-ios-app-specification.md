# 未踏マップ iOSネイティブアプリ 仕様設計書 v1.0

作成日: 2026-08-01 / ステータス: オーナー承認待ち

---

## 1. プロダクト定義

### 1.1 目的
iPhoneが自動で位置ログを取り続け、「行ったことがある場所」を霧が晴れた領域として地図に可視化し、未訪問エリアへの外出を促す。ユーザーの行動範囲を広げ、日常に探索の動機を作る。

### 1.2 コアバリュー
- **ゼロ運用**: 一度許可すれば、アプリを開かなくても記録が続く
- **電池を犠牲にしない**: 常時記録でもバッテリー影響を体感させない
- **データは自分のもの**: 全データ端末内保存。サーバー送信なし。いつでもエクスポート可能

### 1.3 成功指標(個人利用MVP)
| 指標 | 目標 |
|---|---|
| 記録の連続稼働 | 7日間、手動操作ゼロで欠損なし |
| バッテリー影響 | 標準モードで1日あたり1%未満 |
| 行動変化 | 提案を受けて未踏セルを訪問した回数: 週1回以上 |

### 1.4 スコープ
| フェーズ | 内容 |
|---|---|
| MVP (v1.0) | 自動ログ / 霧マップ / 未踏提案 / 到達通知 / タイムライン・GPXインポート / エクスポート |
| v1.1 | Apple Watchアプリ+コンプリケーション / 週次レポート通知 / iCloud同期 |
| 将来 | 実績システム / 地域メッシュ統計連携(人口・POI密度) / 精密経路モード |

## 2. システム構成

```
┌─ iPhone ────────────────────────────────────────┐
│ SwiftUI App                                     │
│ ├ LocationEngine   … CoreLocation 制御・記録    │
│ ├ GridEngine       … セル変換・踏破判定         │
│ ├ FogRenderer      … MapKit カスタムオーバーレイ│
│ ├ QuestEngine      … 未踏セル探索・スコアリング │
│ ├ Store (SwiftData)… points / cells / quests    │
│ └ Importer/Exporter… GPX / CSV / Timeline JSON  │
├─ OS サービス ───────────────────────────────────┤
│ Significant Location Change / CLVisit /         │
│ Region Monitoring / UserNotifications           │
└─────────────────────────────────────────────────┘
（v1.1: watchOS App — WatchConnectivity経由で統計・提案を受信）
```

サーバーなし。全処理オンデバイス。

### 2.1 技術スタック(比較と選定)
| 項目 | 選定 | 代替案 | 選定理由 |
|---|---|---|---|
| UI | SwiftUI (iOS 17+) | UIKit | 実装量最小。個人利用でOS縛りの不利益なし |
| 地図 | MapKit | Mapbox | 無料・審査不要・カスタムオーバーレイで霧描画可能。Mapboxは従量課金と依存が増える |
| 永続化 | SwiftData | GRDB / Core Data | 想定データ量(年10万行未満)ではSwiftDataで十分。移行コスト最小 |
| セル体系 | 独自等角グリッド | JIS地域メッシュ / Geohash | §4参照 |

## 3. 位置ログ取得仕様(本アプリの心臓部)

### 3.1 記録モード
| モード | 使用API | 粒度 | 電池 | 既定 |
|---|---|---|---|---|
| 標準(常時) | Significant Location Change + CLVisit | 約500m移動ごと+滞在地点 | ほぼゼロ | ON |
| 精密(手動) | `startUpdatingLocation` + background updates | 数十m連続 | 中 | OFF(散歩時に手動ON、または将来ジオフェンス連動) |

設計判断: **標準モードだけでMVPの価値は成立する**。セル粒度(250m〜1km)に対してSLCの約500m粒度は十分。精密モードは「散歩の軌跡を残したい」欲求向けのオプション。

### 3.2 動作要件
- 権限: 「常に許可」+ 正確な位置。取得は §7.1 の段階的オンボーディングで行う
- SLC / CLVisit はアプリ終了後もOSがアプリを再起動して配信する → `application(_:didFinishLaunchingWithOptions:)` で location キー起動を検知し、UIなしで記録処理のみ実行
- Background Modes: `location` を有効化(精密モード用)
- 記録処理は起動から数秒で完了させる(バックグラウンド実行時間制限対策)

### 3.3 記録パイプライン
```
CLLocation受信
 → 精度フィルタ(horizontalAccuracy > 100m は棄却 ※標準モードは200m)
 → 重複排除(直前記録から 50m未満 かつ 60秒未満 は棄却)
 → Point保存 → 所属セル計算 → 未踏セルなら Cell新規作成(初到達日時記録)
 → 到達がアクティブなクエスト先セルなら達成処理(§6.4)
```

### 3.4 エッジケース
| ケース | 挙動 |
|---|---|
| 権限を「使用中のみ」に格下げされた | バナーで常時記録が止まっている旨を表示 |
| 位置精度が悪い(地下・屋内) | フィルタで棄却。欠損は許容(セル単位なので影響小) |
| 機内モード/圏外 | GPSは動作するため記録継続 |
| 海外 | グリッドは全世界一様なのでそのまま動作 |

## 4. セル(メッシュ)仕様

### 4.1 体系の比較
| 体系 | 長所 | 短所 |
|---|---|---|
| **独自等角グリッド(採用)** | プロトタイプとロジック・データ互換。全世界一様。実装最小 | 統計データとの直接照合不可 |
| JIS地域メッシュ (X 0410) | 国勢調査等の統計と直結(将来のPOI/人口スコアに有効) | 日本国内限定。コード変換実装が必要 |
| Geohash | 汎用・共有しやすい | 緯度でセル縦横比が変わり見た目が不均一 |

採用: 独自等角グリッド。将来の統計連携時に「独自グリッド→地域メッシュ変換関数」を追加すれば両立できるため、今はコストを払わない。

### 4.2 定義
- `cellKey = "\(floor(lat / s))_\(floor(lng / s))"`、s ∈ {0.0025, 0.005, 0.01}(約250m / 500m / 1km)
- 記録時に**3粒度すべてのセルを同時登録**する(粒度切替を再計算なしで即時反映するため。ストレージ増は軽微)

### 4.3 データモデル(SwiftData)
```swift
@Model final class Point {
  var lat: Double; var lng: Double
  var timestamp: Date
  var accuracy: Double
  var source: String   // "slc" | "visit" | "precise" | "import"
}
@Model final class Cell {
  @Attribute(.unique) var key: String   // "size:i_j" 例 "0.005:7212_27934"
  var sizeClass: Int    // 0=250m 1=500m 2=1km
  var firstVisit: Date
  var lastVisit: Date
  var visitCount: Int
}
@Model final class Quest {
  var targetKey: String
  var createdAt: Date
  var completedAt: Date?
  var distanceM: Double
}
```
インデックス: `Cell.key`(unique)、`Point.timestamp`。

## 5. 霧レンダリング仕様

- `MKOverlay` 準拠の `FogOverlay`(全世界矩形)+ カスタム `FogOverlayRenderer`
- 描画: `draw(_ mapRect:zoomScale:in:)` で (1) 対象mapRectを霧色 `#0E1520` α0.78 で塗り、(2) そのrectに交差する踏破セルを blend mode `.clear` でくり抜く
- 踏破セルはメモリ上の `Set<CellKey>` + 空間インデックス(i,j範囲クエリ)で照会。タイル単位描画のためセル数が数万でも一定コスト
- 晴れた縁のぼかし: くり抜き矩形に2ptのソフトエッジ(v1.0はオプション、負荷次第で削る)
- 粒度切替・霧ON/OFFは `setNeedsDisplay()` のみで反映

却下案: `MKPolygon` + interiorPolygons(プロトタイプ方式)。セル数千で頂点更新コストが増えるため、タイル描画方式を採用。

## 6. 未踏提案エンジン(QuestEngine)

### 6.1 MVPアルゴリズム
プロトタイプと同一の螺旋探索を基礎に、スコアリングを追加。

```
候補 = 現在地セルから螺旋探索した未踏セル上位N(=30)
score(c) = w_d · proximity(c)        // 近いほど高い(徒歩30分内を優遇)
         + w_p · poiBonus(c)         // MKLocalSearchでカフェ/公園/神社等がヒットすれば加点
         + w_n · directionNovelty(c) // 過去の提案・移動方位と異なる方角を加点
初期重み: w_d=1.0, w_p=0.6, w_n=0.4(設定画面で調整可、検証対象)
```

### 6.2 提案トリガー
| トリガー | 内容 |
|---|---|
| 手動 | マップ画面のボタン(MVP必須) |
| 週末プッシュ | 土日 9:00、その週に未踏訪問がなければ通知(設定でOFF可) |
| 週次レポート | 日曜 20:00「今週 +12セル踏破、踏破率 x%」(v1.1) |

### 6.3 提示内容
方角+距離(「北東へ 1.2 km」)、セル中心座標、POIヒット時はその名称、マップ上に破線とターゲット表示。「マップアプリで経路を開く」ボタン。

### 6.4 到達判定
クエスト受諾時にターゲットセル中心へ **半径=セル辺長/2 のジオフェンス**(Region Monitoring)を登録。入域でアプリが起こされ、達成記録+通知「🌫→☀ 霧が晴れました」。ジオフェンスは最大20件制限があるため、アクティブクエストは常に1件。

| 画面 | 要素 |

| 統計 | 踏破セル数、記録点数、連続記録日数、月別推移グラフ |

### 7.1 権限取得フロー(重要)
1. 初回起動: 価値を説明した上で「使用中のみ」を要求(拒否率を下げる)
2. 初回記録成功後: 「アプリを閉じても記録を続けるには常時許可が必要」画面 → Always要求
3. Info.plist purpose string は具体的に書く: 「移動の記録を自動で続け、訪れた場所の霧を晴らすために位置情報を常に使用します。データは端末外に送信されません」

## 8. インポート / エクスポート

| 形式 | 方向 | 仕様 |
|---|---|---|
| Google タイムライン JSON | In | `latitudeE7/longitudeE7` および `"lat°, lng"` 文字列形式の両方に対応(プロトタイプのパーサを移植) |
| GPX | In / Out | trkpt/wpt/rtept 読取。エクスポートは全Pointをtrkとして出力 |
| CSV | In / Out | `timestamp,lat,lng,accuracy,source` |
| ネイティブバックアップ | Out | 全テーブルJSON(ファイルApp経由で保存) |

インポート時は §3.3 と同じ重複排除を通す。初期データとして並行稼働中のタイムラインを取り込み、記録の空白をなくす。

## 9. 非機能要件

| 項目 | 目標 |
|---|---|
| バッテリー | 標準モード ≤1%/日、精密モード ≤5%/時 |
| ストレージ | 5年運用で100MB未満(Point年5万件想定) |
| 描画 | 霧オーバーレイ含めマップ操作60fps、セル5万件で劣化なし |
| 起動 | バックグラウンド起動→記録完了まで3秒以内 |
| プライバシー | 位置データの外部送信ゼロ。分析SDK不使用。App Privacy「データ収集なし」申告 |
| オフライン | 記録は完全オフライン動作。地図タイルのみ要ネットワーク(キャッシュはMapKit任せ) |

## 10. テスト設計

### 10.1 ユニットテスト
- GridEngine: 座標→cellKey変換(境界値: 0度またぎ、負値、粒度3種)
- 記録フィルタ: 精度棄却・重複排除の閾値境界
- Importer: タイムラインJSON 2形式 / GPX / CSV(壊れた行を含む)
- QuestEngine: 全踏破時・孤島状(飛び地)踏破時の探索終了、スコア順位

### 10.2 シミュレーションテスト(再現可能)
- Xcodeの位置シミュレーション用GPXを3本用意: ①久喜駅周辺散歩 ②電車移動(高速・低頻度) ③精度劣化を含む屋内
- GPXリプレイ→期待セル集合のスナップショットと突合(回帰テストとしてCIなしでも `⌘U` で再現)

### 10.3 フィールドテスト手順(7日間)
1. Day0: タイムラインJSONを初期投入、バッテリー記録開始(設定→バッテリーのスクショを毎晩)
2. Day1-7: 通常生活。手動操作禁止。毎晩「本日の新規Point数 / 新規セル数」を統計画面で記録
3. 判定: 欠損日ゼロ・電池影響1%/日未満・SLC由来Pointが1日20件以上あれば合格
4. 週末にクエストを1回実行し、到達通知の発火を確認

### 10.4 電池・異常系
- 精密モード1時間連続でのバッテリー消費実測
- 権限格下げ→バナー表示、再許可→自動復帰
- 強制終了後にSLCで再起動して記録されること(実機のみ検証可)

## 12. リスク

| リスク | 影響 | 対策 |
|---|---|---|
| SLCの発火頻度が生活圏で低すぎる | セルが晴れない | CLVisit併用で滞在は必ず拾う。粒度1km表示で体感を補正 |
| 常時許可の心理的ハードル | 記録開始できない | 段階的許可+送信ゼロの明示(§7.1) |
| iOSのバックグラウンド仕様変更 | 記録停止 | OSアップデート後にフィールドテスト§10.3を再実行する運用ルール |
| 霧描画のパフォーマンス | 操作感悪化 | タイル描画方式を採用済み。5万セル負荷試験をM2の完了条件に含める |
